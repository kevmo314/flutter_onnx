# flutter_onnx

Load an ONNX graph once and run it locally on Flutter web, Android, or iOS. The Dart package implements protobuf model decoding, graph execution, tensor broadcasting and CPU kernels. It has zero runtime dependencies. A companion Flutter plugin can send matrix products to the device.

## Install

Add the core package to your application's `pubspec.yaml`. To enable device acceleration, also add the companion package from the same revision.

```yaml
dependencies:
  flutter_onnx:
    git:
      url: https://github.com/kevmo314/flutter_onnx.git
      ref: main
  flutter_onnx_accelerators:
    git:
      url: https://github.com/kevmo314/flutter_onnx.git
      ref: main
      path: accelerators
flutter:
  assets:
    - assets/xor.onnx
```

Copy the included model from [example/assets/xor.onnx](example/assets/xor.onnx) or supply your own model. The example graph takes two bits and returns their exclusive OR.

```dart
import 'package:flutter/services.dart';
import 'package:flutter_onnx/flutter_onnx.dart';
import 'package:flutter_onnx_accelerators/flutter_onnx_accelerators.dart';

Future<void> predict() async {
  final asset = await rootBundle.load('assets/xor.onnx');
  final session = OnnxSession.fromBytes(
    asset.buffer.asUint8List(asset.offsetInBytes, asset.lengthInBytes),
  );
  final inputs = {'bits': Tensor.float32([1, 2], [1, 0])};
  final backend = await createMatMulBackend();
  try {
    final output = await session.runAsync(inputs, backend: backend);
    print(output['xor']!.values.single); // 1.0
  } finally {
    await backend?.close();
  }
}
```

For CPU-only use, depend on `flutter_onnx` alone and call `session.run(inputs)`. Reuse the session and backend across predictions. Inspect `session.inputs` and `session.outputs` for names, element types and declared dimensions. Named symbolic dimensions bind independently on each call.

## Device kernels

| Target | Backend | Dispatch |
| --- | --- | --- |
| Web | WebGPU | A WGSL compute shader multiplies two FLOAT matrices. Requires WebGPU in a secure context such as HTTPS or localhost. |
| Android | Android Neural Networks API | On API 29+ a supported GPU or accelerator executes a fully connected operation. Other Android devices use Dart. NNAPI was deprecated in Android 15 and availability varies by driver. |
| iOS | Metal Performance Shaders | A Metal command queue executes MPSMatrixMultiplication on compatible devices. The plugin targets iOS 13+. |

`runAsync` offloads nonempty rank-two FLOAT `MatMul` and the matrix product in `Gemm`. Transposition, scaling, bias and all other operators run in Dart. When a device declines a product, the scheduler computes it on the CPU. Pass `onAccelerated: (node) => print(node)` to observe successful dispatches. Transfers, weight transposition and compilation can outweigh device computation for small or frequently repeated products. The implementations currently transfer buffers per call.

## Model compatibility

The loader accepts binary ONNX ModelProto, IR versions 7–10, default-domain opsets 13–17, and a topologically ordered dense inference graph. External weight files, model-local functions, quantized tensors, custom domains, control flow and training graphs are outside this release's coverage. Unsupported operators or attributes raise an error. The package implements a subset of the ONNX operator set.

| Operations | Coverage |
| --- | --- |
| Arithmetic | Add, Sub, Mul, Div with multidirectional broadcasting |
| Pointwise | Relu, LeakyRelu, Sigmoid, Tanh, Abs, Neg, Exp, Log, Sqrt |
| Linear algebra | MatMul including vectors and broadcast batches, Gemm including optional bias and transpose flags, Softmax along a chosen axis |
| Data movement | Identity, tensor-valued Constant, Concat, Flatten, Reshape, Transpose |
| Neural networks | Grouped 2-D NCHW Conv, 2-D AveragePool and MaxPool (values output), GlobalAveragePool, inference-mode BatchNormalization |

Arithmetic kernels use FLOAT (float32). Data movement also supports INT64, restricted to integers in the range −(2⁵³−1) through 2⁵³−1 for consistent web behavior. Initializers may use embedded little-endian raw data or protobuf repeated values. Pooling and convolution support explicit pads, VALID, SAME_UPPER and SAME_LOWER. The CPU implementation is synchronous and runs on the calling isolate.

## Run the example and tests

```sh
cd example
flutter pub get
flutter run -d chrome
# Or use flutter devices and pass an Android or iOS device ID to flutter run -d.
```

From the repository root, run `dart pub get` and `dart test -p vm -p chrome`. The tests compare graph outputs with committed vectors generated by ONNX's Python reference evaluator. Python is only used to regenerate fixtures. From `example`, run `flutter test integration_test/inference_test.dart -d <device-id>` to exercise the bundled model on mobile. The dedicated browser test can require a successful WebGPU dispatch with `flutter test --platform chrome --dart-define=REQUIRE_WEBGPU=true test/webgpu_test.dart`.
